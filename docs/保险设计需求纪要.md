# 保险设计需求纪要

## 2026-08-13：avoidance fallback 待办

### 当前决定

自适应 TEB 暂时删除 `avoidance -> baseline` 的即时 fallback，不在本轮添加替代
保险。原因是 baseline 使用较小 footprint；当激光仍判定锥桶威胁存在时，直接用
baseline 继续输出速度会绕过 avoidance 的安全外形，并可能把“多拓扑暂时没有可行
控制”转化为碰撞。

当前行为如下：

1. selector 进入 avoidance 后，由多拓扑 TEB 输出控制；
2. avoidance 本周期无可行控制时输出零速度并向 `move_base` 返回失败；
3. 不改变 selector 模式，不在同一周期尝试较小 footprint 的 baseline；
4. `move_base` 原有 controller patience、清图和恢复行为暂时保留。这些机制也应在
   后续全任务保险设计中统一审查，不能视为已经完成的 avoidance fallback。

baseline 在普通区连续失败且激光同时确认路径附近存在紧凑障碍时，尝试一次
avoidance 的逻辑不属于本条待办：它不会缩小 footprint，当前继续保留。

### 后续 fallback 的安全需求

统一实现保险时，avoidance fallback 至少满足以下要求：

- **安全边界不可降级**：锥桶威胁仍存在时，fallback 不得换用比 avoidance 更小的
  footprint、`min_obstacle_dist` 或等效碰撞边界。
- **先停再恢复**：首次无可行控制先发送零速度；不得在同一控制周期用不安全轨迹
  顶替。连续失败达到明确阈值后才进入恢复状态。
- **传感器有效性前置**：只使用时间戳新鲜、束数合格的激光/代价地图证据。激光
  过期、TF 失败或分析异常时保持停车，不能按“路径已清空”处理。
- **威胁解除有滞回**：仅在连续若干帧净距恢复、且满足最短保持时间后，才允许
  回到 baseline；单帧清空不构成解除条件。
- **安全恢复配置**：首选同等大 footprint 的单拓扑 safety TEB、缩短规划视野或
  原地等待全局重规划；不得复用当前小 footprint baseline 作为锥桶区保险。
- **有界重试**：规定连续不可行次数、最长停车时间和恢复次数；达到上限后明确
  上报导航失败，禁止无限振荡、无限清图或反复切换拓扑。
- **全局规划协同**：局部持续不可行时可以请求官方 GlobalPlanner 重规划，但不
  得自行篡改目标或悄悄发布一条缺少可追溯性的替代全局路径。
- **恢复动作审查**：清除代价地图、旋转恢复、倒车等 move_base 既有行为要逐项
  验证；当真实激光仍观测到障碍时，不得仅因清图而把障碍当作消失。
- **状态可观测**：记录触发原因、连续失败计数、激光年龄、路径净距、当前/候选
  planner、停车时长、恢复次数和最终退出原因。

### 建议状态机

`AVOIDANCE_ACTIVE -> SAFE_STOP -> SAFE_REPLAN -> AVOIDANCE_ACTIVE`。

- `SAFE_STOP`：零速度并积累连续有效失败证据；
- `SAFE_REPLAN`：使用同等安全边界进行有限次恢复或等待全局重规划；
- 威胁连续解除后才允许 `SAFE_STOP/SAFE_REPLAN -> BASELINE`；
- 达到总时限或次数上限后进入 `ABORT`，由任务层统一处理。

具体次数和时限暂不写死，应先从本轮压力测试的
`avoidance_infeasible_no_fallback` 样本、停车持续时间和全局重规划时延中取数。

### 验收条件

未来实现不能只以“任务最终跑通”判定通过，至少需要：

1. 单元测试覆盖首次不可行停车、连续失败、激光过期、威胁解除滞回和重试上限；
2. 固定场景 007、009、012、032 端到端压力测试，分别统计碰撞、卡死、导航失败、
   fallback 次数和 fallback 后净距；
3. 构造 avoidance 暂时不可行的场景，确认 fallback 全程不输出违反大 footprint 的
   速度；
4. 前序导航回归，确认保险状态机不会在普通厂区误触发或引入振荡；
5. 日志能区分“局部规划不可行”“传感器失效”“全局无路”和“保险耗尽”。

### 本轮不实现

- 不新增 avoidance fallback planner；
- 不按固定坐标或任务阶段强制降级；
- 不用 baseline 小 footprint 越过锥桶威胁；
- 不把无限等待或无限恢复当作保险。

### 2026-08-13 首轮无 fallback 观察

固定场景 007 使用 `0.15 m` avoidance footprint 半边长、全局
`inflation_radius=0.35 m`、`cost_scaling_factor=7.5` 和稳定 HCP 参数完成三轮
GUI 验证：2 轮任务完成，1 轮投递导航失败；三轮前序导航均完成。失败轮中
`cone_14` 在 avoidance 生效期间移动约 `0.227 m`，之后 move_base 因持续振荡而
耗尽恢复行为。该碰撞不是由 fallback 引起，说明 safety TEB 本身仍需提高实际
障碍约束与可执行轨迹的一致性。

成功的第 3 轮出现一次 `avoidance_infeasible_no_fallback`，规划器按预期停车且随后
恢复完成任务。验证同时发现普通诊断 0.5 秒节流会漏记紧邻上一条周期样本的失败；
后续版本已把 `avoidance_infeasible_no_fallback` 和 `baseline_infeasible` 改为强制
发布，保险统计应以新版本为准。
