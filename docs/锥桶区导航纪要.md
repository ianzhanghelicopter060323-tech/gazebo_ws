# 锥桶区导航纪要

## 2026-08-13：TEB 后续开发路径

当前实验结论：全程启用激进多拓扑 TEB 对锥桶区路径选择有一定提升，
但只有进一步扩大局部“禁止区”后才可能形成明显的避障收益；同一配置用于
前序导航时又会造成大范围振荡、卡死甚至侧翻。因此不再继续寻找一组同时兼顾
两段路线的固定 HCP 参数。

后续按以下顺序推进：

1. 暂时恢复单拓扑 TEB，先完成前序导航到 seq35 的 100 轮稳定性基线。
2. 单独手动验证“保守参数 + 较大禁止区 + 多拓扑 TEB”在锥桶区的收益上限。
3. 若双参数 Profile 的效果和规则解释均确认可行，正式采用两套 TEB：
   - `automatic_navigation`：较激进、单拓扑，用于前序导航、抓取及准备位姿2；
   - `cone_zone_avoidance`：较保守、多拓扑、较大禁止区，用于锥桶区。
4. 若比赛中途切换 Profile 不可用，则 fork TEB 实现自适应局部规划器：两套
   参数在启动时一次性加载，由实时激光雷达/局部代价地图判断环境复杂度，
   在算法内部选择单拓扑或多拓扑，不在运行中写 ROS 参数。官方 GlobalPlanner
   和全局代价地图保持不变。

这里的“禁止区”需要同步考虑三项：局部代价地图的
`footprint + footprint_padding`、TEB 的 `footprint_model`，以及
`min_obstacle_dist`。`inflation_radius`主要提供软代价偏好，不能单独视为硬禁止区。

### 前序导航 100 轮基线

使用 `run_pre_navigation_trials.py`。脚本默认执行恰好 100 次独立仿真，不会通过
失败后补跑来凑齐 100 个成功样本。每轮执行当前拟合路线到 seq35，机器人进入
seq35 目标点 `0.15 m` 的 XY 半径即算到达，不要求最终朝向；OCR、抓取和配送均
不参与本项测试。

```bash
cd /home/ianichinose/gazebo_ws
source devel/setup.bash
python3 script/run_pre_navigation_trials.py
```

需要观察 Gazebo 和 RViz 时使用：

```bash
python3 script/run_pre_navigation_trials.py --gui
```

测试前必须关闭其他 Gazebo 仿真。脚本会拒绝在已有 `gzserver` 时启动，以避免
双 Gazebo 竞争资源导致仿真卡死或动作异常。默认使用隔离端口
`ROS_MASTER_URI=:1132` 和 `GAZEBO_MASTER_URI=:1133`。

结果分别写入：

- `script/logs/pre_navigation_trials_<时间>_ros1132/trials.csv`；
- 同目录的 `summary.json` 和逐轮 `roslaunch.log`；
- `data/pre_navigation_test/<同名运行目录>/` 中的 Gazebo 状态录像。

稳定性判定以 `100/100` 到达、无导航失败、无卡死、无侧翻为目标；启动或录像
基础设施错误需要与规划器失败分开统计。成功轮录像仍按既有清理逻辑处理：先运行
`prune_successful_gazebo_recordings.py` 预览，确认后再加 `--apply`。
