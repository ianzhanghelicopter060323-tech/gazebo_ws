# 锥桶区导航纪要

## 2026-08-13：激光自适应 TEB V1 已落地

已新增 `smart_factory_adaptive_teb/AdaptiveTebLocalPlannerROS`。它继续使用官方
`global_planner/GlobalPlanner`，不替换或自行发布全局路径，在一个
`nav_core::BaseLocalPlanner` 插件内部同时持有两套启动时固定的官方 TEB：

- `baseline`：100 轮前序导航验证过的单拓扑参数；
- `avoidance`：使用更大的碰撞外形、独立障碍权重并启用 HCP 多拓扑；
- 正常状态只运行 baseline；720 束 `/scan` 中持续出现贴近当前官方全局路径的
  紧凑障碍时切到 avoidance；HCP 无可行控制时停车并返回失败，不再回退到小
  footprint baseline；未来保险需求见 `docs/保险设计需求纪要.md`；
- 不读取 `/gazebo/model_states`，不在线修改 ROS 参数，也不按任务阶段或固定地图
  坐标切换。准备位姿2触发方案仍只作为未采用的备选。

配置位于
`src/gazebo_nav/launch/config/move_base/adaptive_teb_params.yaml`。启动时会校验
配置版本、baseline 必须为单拓扑、avoidance 必须为多拓扑；命名空间错误或缺参
将直接拒绝初始化，避免 TEB 静默回退默认参数。主要激光判据如下：

- 检测距离 `0.08--1.50 m`，分析官方路径前方 `1.20 m`；
- 紧凑聚类宽度 `0.06--0.45 m`。锥桶网格以英寸为单位并放大 10 倍，
  在 `0.0874 m` 激光高度处可见锥体约宽 `0.38 m`；
- 路径走廊半宽 `0.30 m`；单个聚类净距 `<0.30 m`，或两个以上聚类净距
  `<0.35 m`，构成一帧复杂障碍证据；
- 最近 8 帧中至少 5 帧有证据才进入 avoidance；连续 20 帧清空后退出，
  最短保持 `2.5 s`，回退冷却 `2.0 s`；目标 `0.35 m` 内强制 baseline。

## 2026-08-13：TEB 实施前开发路径（已由上节 V1 落地方案取代）

当前实验结论：全程启用激进多拓扑 TEB 对锥桶区路径选择有一定提升，
但只有进一步扩大局部“禁止区”后才可能形成明显的避障收益；同一配置用于
前序导航时又会造成大范围振荡、卡死甚至侧翻。因此不再继续寻找一组同时兼顾
两段路线的固定 HCP 参数。

后续按以下顺序推进：

1. 暂时恢复单拓扑 TEB，先完成前序导航到 seq35 的 100 轮稳定性基线。
2. 单独手动验证“保守参数 + 较大禁止区 + 多拓扑 TEB”在锥桶区的收益上限。
3. 若双参数 Profile 的效果和规则解释均确认可行，正式采用两套 TEB：
   - `automatic_navigation`：较激进、单拓扑，用于前序导航、抓取及准备位姿2；
   - `cone_zone_avoidance`：较保守、多拓扑、较大禁止区，用于锥桶区。
4. 若比赛中途切换 Profile 不可用，则 fork TEB 实现自适应局部规划器：两套
   参数在启动时一次性加载，由实时激光雷达/局部代价地图判断环境复杂度，
   在算法内部选择单拓扑或多拓扑，不在运行中写 ROS 参数。官方 GlobalPlanner
   和全局代价地图保持不变。

这里的“禁止区”需要同步考虑三项：局部代价地图的
`footprint + footprint_padding`、TEB 的 `footprint_model`，以及
`min_obstacle_dist`。`inflation_radius`主要提供软代价偏好，不能单独视为硬禁止区。

## 2026-08-14 暂停点：激光动态入口与滚动通道实验

### 本轮新增逻辑及边界

本轮确实增加了导航逻辑，但没有修改官方 `GlobalPlanner` 的搜索算法，也没有改写
它输出的全局路径。新增内容位于任务层，流程为：

1. 抓取后先到配送区名义入口附近；
2. 用新鲜 `/scan` 在名义入口周围投影一个障碍净距更大的安全入口；
3. 进入锥桶区后最多滚动发布 2 个短视野中间目标；
4. 每个候选先调用 `/move_base/make_plan`，只有官方全局规划器确认可达，且其规划
   路径满足最低激光净距时，才把该坐标作为普通 `move_base` 目标发布；没有合格
   候选时直接失败，不回退到已知不安全的名义点。

因此这里新增的是“激光选点 + 官方规划可达性筛选 + 发布中间目标”的外层决策，
不是一套替代全局规划器。此前已经实现的 `AdaptiveTebLocalPlannerROS` 仍负责根据
激光威胁在 baseline 单拓扑 TEB 和 avoidance 多拓扑 TEB 之间自适应选择；本轮
没有继续修改 TEB 内部候选优化/打分算法。

## 待评审：动态滚动中间点后续算法调试路线

本节是后续讨论基线，不代表已经批准实施。恢复开发前，应由用户进一步了解并
确认、修改以下方向；在方案确认前不继续叠加参数改动。

### 总体目标与不变量

- 目标是在随机锥桶分布中优先引导机器人走可执行的宽通道，并尽量做到零碰撞
  完赛。
- 保留官方 `GlobalPlanner` 生成全局路径、TEB 执行局部控制的主体结构；动态
  中间点只在任务层提供短视野引导目标。
- 候选点必须同时满足激光安全性和 `/move_base/make_plan` 全局可达性；暂不添加
  不安全 fallback。
- 一次只改变一个层面的因素。每次实验必须记录选择坐标、横移量、直行净距、
  进入段净距、官方规划路径净距和离开段净距，避免只凭 GUI 观感调参。

### 阶段 A：确定当前 `0.20 m` 可行性边界

保持其余配置不变，先对 009 做 1 轮 GUI 冒烟，验证尚未实测的：

```yaml
channel_hard_min_clearance: 0.20
```

根据结果分流：

- 零碰撞完赛：停止调参，进入 009、007 各 3 轮验证。
- 没有合格候选：判定当前单一前进距离的候选空间不足，不继续下调硬净距。
- 找到候选但仍碰撞：判定激光点净距不能代表 footprint 与锥桶底座的真实碰撞
  净距，转入阶段 C。
- 官方可达但 TEB 振荡或无法执行：判定全局可达性不足以描述局部可执行性，单独
  记录并讨论 TEB 可执行性筛选，不与候选空间扩展同时修改。

### 阶段 B：从单一横截面扩展为多前进距离候选

当前候选全部位于机器人前方 `0.55 m` 的同一横截面。若该横截面恰好落入全局
膨胀区，即使更近处存在可用踏脚点，也会被错误判为“没有候选”。拟议改为同时
搜索约 `0.35 m`、`0.45 m`、`0.55 m` 三个前进距离，每个距离仍按当前方式左右
横向采样。

初始建议：

- 保持 `channel_lateral_max=0.45 m`、`channel_lateral_step=0.05 m`；
- 先粗筛激光净距，再对少量入围点调用 `make_plan`，控制服务调用数量；
- 必要时只在最佳粗候选附近增加 `0.025 m` 的局部精细搜索，不直接将全区域采样
  加密；
- 评分中加入很小的“短步惩罚”，避免长期选择最近点而增加无意义的滚动次数，
  但该项不得压过净距偏好。

阶段 B 的成功标准是至少产生一个官方可达候选并继续前进；若候选数量增加后仍然
没有可达点，应停止扩大搜索范围，先检查代价地图和入口几何，而不是继续暴力增加
采样。

### 阶段 C：将点净距升级为 footprint/锥桶底座感知净空

当前指标是“路径中心线到激光障碍点的距离”。激光可能照到锥桶较窄的腰部，而
碰撞发生在更宽的底座；矩形 footprint 转弯时的扫掠范围也大于简单半宽。因此，
后续拟议计算：

```text
估计真实剩余净空
= 路径中心线到激光点的距离
- 当前路径方向上的机器人 footprint 支撑半径
- 锥桶底座补偿
```

进入段、官方全局路径段和离开段均应使用同一个几何定义。若实现完整扫掠检测代价
过高，可先使用“方向相关矩形支撑半径 + 经模型尺寸或实验确认的锥桶底座补偿”
近似，但补偿值必须在日志和配置快照中显式记录。

阶段 C 实现后，不再把 `0.20/0.36 m` 与旧的中心线净距直接比较，需要重新定义硬
净空与期望净空阈值。若碰撞依旧集中在转弯而直行段净空充足，则再升级为离散姿态
footprint 扫掠检测；不提前实现复杂版本。

### 阶段 D：按官方实际全局路径决定是否介入

当前 `channel_trigger_clearance` 检查机器人朝最终目标的几何直线，而 GlobalPlanner
实际可能已经绕行，或在更远处重新进入窄通道。拟议调整为：

1. 先对最终厂区调用一次 `/move_base/make_plan`；
2. 截取官方路径前方短视野；
3. 计算该路径的瓶颈净空；
4. 只有实际路径过窄时才生成中间点，并围绕路径瓶颈或其前方生成候选。

这样可以减少“直线很窄但官方路径本来就安全”造成的多余介入，也能发现“当前直线
很宽但官方路径稍后贴障碍”的漏触发。应先复用阶段 C 的统一净空定义，再开展本
阶段，避免两套触发指标并存。

### 阶段 E：TEB 局部可执行性与内部候选评分

只有在候选已经满足统一净空、GlobalPlanner 可达，但 TEB 仍反复振荡或选择贴障碍
局部轨迹时，才进入本阶段。优先级为：

1. 先用运行证据确认失败发生在 TEB 局部执行，而非中间目标切换过密或最终目标
   几何不可达；
2. 研究对候选增加低成本的局部可执行性检查，避免发布 TEB 明显无法跟随的点；
3. 若外层筛选仍不足，再考虑小范围 fork TEB，在多拓扑候选比较中加入未来短视野
   的瓶颈净空软惩罚；
4. 保持硬可行阈值与宽路软偏好分离，使窄但可通行的路线仍可作为完赛通道。

不得仅因单轮振荡就立即扩大 HCP classes、samples 或优化迭代数；现有
`3 classes / 20 samples / 4+3 iterations` 已是经过实时性实验确定的预算基线。

### 参数调整优先级

1. 先验证 `channel_hard_min_clearance=0.20 m`，不继续降低。
2. 无候选时优先增加多前进距离采样，而不是提高横移上限或降低安全底线。
3. 有候选但碰撞时优先修正净距几何，不继续堆叠 `clearance_weight`。
4. 触发错误时改为检查官方实际路径，再评估 `channel_trigger_clearance`。
5. `channel_desired_clearance` 可在真实净空定义稳定后重新标定；当前 `0.36 m` 只
   是中心线点净距下的经验软目标。
6. `channel_clearance_weight=20.0` 与 `channel_lateral_weight=0.10` 已强烈偏向宽路，
   暂不继续放大两者差距。
7. `channel_max_waypoints=2` 暂时保留；只有日志证明通道长度导致两步不足，才增加
   到 3，且必须检查是否引入频繁目标切换。

### 统一停止条件

- 筛选实验中约 90 秒没有明显接近目标或跨过瓶颈，停止该轮并保存日志/录像。
- 任一场景 3 次中出现 1 次碰撞、导航失败、卡死或侧翻，该参数组不通过。
- 如果某阶段连续两种合理配置均在同一几何位置以同一原因失败，停止同层调参，
  转入下一算法层或重新审视问题假设。
- 若新增候选明显增加规划延迟、控制周期频繁超过 `0.5 s`，停止扩大采样并加入
  分级预筛/候选数量上限。
- 每个阶段先只测试 009 一轮；能继续前进并完赛后才扩展到 009、007 各 3 轮，
  最后才恢复 007、009、012、032 的完整压力测试。

### 新暴露的算法边界

当前候选是“全局路径沿程锚点 + 局部法向横移”，并且评分中净距权重远
大于横移代价。算法只约束“官方可达 + 路径净距”，没有“候选必须位于
锥桶阵内/必须穿过某个锥桶间隙”的语义约束。因此它合理地但不符合本
轮目标地偏向锥桶阵外侧的高净距点。继续增大前视/横移会加重这种倾向，
不应作为下一步。

下一步建议先在以下方向中做决策，再改代码：

1. **瓶颈后锚点 + 锥桶区边界门**：继续使用官方全局路径，但候选的
   沿程位置改为当前瓶颈之后，并要求候选位于锥桶区入口面之后。该方案
   改动小，但如果只用固定地图边界，会弱化“根据实时障碍动态选点”的
   一般性。
2. **基于激光点簇的间隙门候选（当前首选）**：从激光连续点簇中识别
   紧凑锥桶簇，对两个锥桶簇之间的可通行间隙生成“门”，候选点放在门
   中心或最大化两侧真实剩余净空的位置。然后仍使用官方
   `make_plan`、`0.20 m` 硬门槛、候选到终点短前缀和 TEB 执行。这能直接
   表达“选一个锥桶间的宽通道”，而不是间接用法向横移把路径拉到
   区外。代码量高于方案 1，但与已有 selector 中的紧凑点簇识别思路一致。
3. **允许区外绕行，但显式定义为拓扑候选**：如果规则与场地可行域
   允许机器人在锥桶阵外侧绕行，则当前点不一定是错误，但应将其单独命名
   为“区外拓扑路线”，增加地图边界/禁止区检查，并在压力测试中单独统计。
   该方向不能继续以“锥桶区内动态通道选择”名义验收。

## 2026-08-14 分阶段 60° 扇形候选实现

用户确认最近两轮的主要问题不是“选不到点”，而是进入后所选点回到了
前序导航走廊。例如上轮安全入口约为 `(-0.921,-1.351)`，入口朝向约为
`-89.6°`，选中点却为 `(-0.077,-1.087)`；其 `y` 增加约 `0.264 m`，位于
入口朝向的后半平面。因此本轮将“官方路径锚点 + 法向横移”候选替换为
明确的极坐标扇形候选。

### 扇形的更新边界

- 扇形顶点在**每次重新选点时**更新为当前机器人位置。
- 已发布的中间点在 move_base 执行期间保持固定，不实现连续移动目标。
- 第 1 个滚动点的中轴固定为实际激光投影后 `safe_entry_pose` 的入口朝向，
  不跟随机器人瞬时 yaw。
- 第 2 个滚动点的中轴在选点时转为“当前机器人→任务车间”方向，
  但仍受同一入口前向半平面约束。
- 每次容差到达中间点后，仍先取消旧 action 并等待 move_base inactive，
  再进行下一轮官方 `make_plan`。

### 当前候选参数与硬约束

```yaml
channel_fan_radii: [0.45, 0.70, 0.95, 1.05]
channel_fan_half_angle_deg: 60.0
channel_fan_angle_step_deg: 10.0
channel_min_forward_progress: 0.20
channel_entry_depth_floor: 0.20
channel_entry_axis_waypoints: 1
channel_angular_weight: 0.10
```

对候选 `p`，令 `f_entry` 为入口朝向单位向量，则无论第几轮扇形，都要
求：

```text
(p - safe_entry_pose) · f_entry >= 0.20 m
candidate 在当轮中轴两侧 ±60° 内
candidate 沿当轮中轴的前向分量 >= 0.20 m
```

这三项是候选集硬约束，早于净距评分和 `make_plan`。即使前序走廊的净距
更大，位于入口后方的点也不会进入规划候选。选择后仍保留：

- `channel_make_plan_tolerance=0.0` 精确全局可达检查；
- `channel_hard_min_clearance=0.20 m` 官方路径硬门槛；
- 候选到最终车间的官方路径短前缀检查；
- 受控起始逃逸规则；
- 净距主导评分，`channel_angular_weight=0.10` 只是很小的中轴偏好。

日志新增 `phase`、`axis_yaw_deg`、`radius`、`fan_angle_deg`、
`forward`、`entry_depth` 和失败时的 `sector_rejected`。这些字段可直接区分
“扇形太小”、“入口深度门槛太严”与“官方全局路径净距不足”。
