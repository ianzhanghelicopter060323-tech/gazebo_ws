# seq35 识别压力测试与正确率补救方案

## 1. 文档目的

本文定义 seq35 物块识别压力测试、失败证据留存、恢复观察位姿设计和独立验证方法。目标是在不改变正式 200 次实验配置、不修改原始随机生成脚本的前提下，回答以下问题：

1. seq35 合法刷新区域中是否存在稳定的视觉盲区；
2. 第 55 次实验的零检出是偶发事件，还是边界位置可重复触发的问题；
3. 一个类别无关的备用观察位姿能否可靠挽救正常位姿的识别失败；
4. 补救方案是否真正提高端到端识别抓取成功率，而不是只适配一个已知失败坐标。

压力测试结果是正式 200 次实验之外的补充证据，不得混入正式实验成功率。

## 2. 已知现象与基本判断

正式 200 次实验最终完成 195 次端到端成功；198 次完成了正确目标选择。5 次失败中，第 44 次属于导航停滞，第 55 次属于 seq35 零有效识别，第 131、142、176 次发生在正确识别之后的抓取阶段。因此，本压力测试只针对第 55 次暴露的 seq35 召回问题，不把另外三次抓取失败混为 OCR 问题。

第 44 次在导航阶段因拟合路径进度停滞而失败，不属于 seq35 识别抓取问题。第 55 次已经完成到 seq35 的导航和机械臂观察动作，但两次定位请求均得到：

```text
no stable 3/5 RGB-D vote (0 valid observations)
```

对应帧的 OCR 日志为：

```text
label=unknown confidence=0.000 text=
```

当时 seq35 内的电子类物块坐标约为：

```text
x = -0.935
y = -0.658
yaw = -1.5708
```

seq35 当前合法刷新范围为：

```text
x ∈ [-0.95, -0.77]
y ∈ [-0.69, -0.36]
yaw = -1.5708
```

因此第 55 次样本靠近 `x` 下边界和 `y` 下边界。现有证据支持“物块文字位于画面边缘、发生裁切或严重透视，导致文字检测器没有输出”的推测，但仅凭日志还不能把它确定为唯一原因。压力测试需要同时保存图像和几何状态来验证该推测。

需要区分三类指标：

- **分类精度**：已经接受的分类中有多少类别正确；
- **识别召回率**：合法场景中有多少次能够产生稳定、可接受的识别；
- **端到端成功率**：导航、识别、定位和抓取全部成功的比例。

第 55 次首先暴露的是识别召回/视野覆盖问题，而不是把一种物块稳定误判成另一种类别。

## 3. 实验隔离与可审计性

### 3.1 不修改原始生成策略

不得为压力测试修改：

```text
src/car3/scripts/spawn_cubes.py
```

应新增独立压力测试脚本，例如：

```text
script/run_seq35_stress_trials.py
```

建议流程为：

```text
正常启动完整仿真
→ 等待原始 spawn_cubes.py 完成
→ 压力测试脚本通过 Gazebo 服务设置测试模型状态
→ 将指定类别放到本轮预先声明的 seq35 坐标
→ 将另外两类分别放在 seq36、seq37 的合法位置
→ 查询 Gazebo 模型状态，确认实际位置
→ 设置机器人到 seq34 起点并初始化定位
→ 自主导航到 seq35
→ 执行正常观察、识别，并按实验阶段决定是否执行抓取或恢复观察
```

这样原始随机策略和正式任务代码保持不变，压力测试中的位置控制明确属于外部试验夹具，不会被误解为正式任务利用真实坐标作弊。

### 3.2 结果严格分区

正式实验、压力测试开发集和压力测试验证集应写入不同根目录：

```text
正式 200 次实验结果/
seq35_stress/development/
seq35_stress/validation/
```

具体根目录由将来的 `--output-dir` 参数指定，本文不固定用户尚未建立的照片目录。

每份汇总必须包含 `experiment_kind` 字段：

```text
main_200
seq35_stress_development
seq35_stress_validation
```

任何压力测试样本都不得加入 `main_200` 的分子或分母。

### 3.3 固定并记录试验清单

每批实验开始前生成只读或追加式清单，至少包含：

```text
case_id, phase, class, requested_x, requested_y, requested_yaw,
start_pose_id, scan_plan_id, repeat_index, seed
```

运行中不得因为某个样本失败而删除该行、替换其结果或用重跑结果覆盖原记录。基础设施故障可以重跑，但原记录必须保留并标记为 `infrastructure_error`，新一轮使用新的 `case_id`。

## 4. 从 seq34 自主导航到 seq35

### 4.1 设计目的

机器人不直接刷新在 seq35 精确观察位，而是从 seq34 自主导航到 seq35，以保留以下真实波动：

- AMCL 初始误差和更新误差；
- 局部规划与最终停车误差；
- 到达位置和朝向的轮间波动；
- 机器人停车后相机视角的自然变化。

这比直接把机器人放在 seq35 更接近正式任务，同时显著缩短了完整路线的压力测试时间。

### 4.2 当前参考起点

当前拟合路径配置中的 seq34 参考点为：

```text
x = -1.2508008601215004
y = -0.853187991210825
yaw ≈ 1.7648638436069304
```

压力测试脚本应从当前运行配置读取该值，或把配置文件路径和文件哈希写入清单，不应在多个脚本中长期维护一份容易过期的硬编码副本。

### 4.3 初始化要求

设置机器人模型状态后，应执行以下检查：

1. 将机器人线速度和角速度清零；
2. 发布与 Gazebo 起点一致的 AMCL 初始位姿；
3. 等待 `/scan`、`map → base_footprint` 和 AMCL 位姿恢复新鲜；
4. 必要时清理导航代价地图；
5. 查询并记录 Gazebo 真值和 AMCL 起点；
6. 再发送从当前路径投影位置到 seq35 的正常导航任务；
7. 到达后同时记录 Gazebo 真值、AMCL 位姿及二者差值。

不能只记录“导航成功”，因为停车误差很可能是 seq35 识别失败的重要解释变量。

## 5. 单类别、单位置实验原则

每个试验用例只在 seq35 放置一个指定类别和一个指定位置，目标类别也设置为该类别。其他两个物块仍放置在 seq36、seq37 的合法区域，避免场景结构和正式任务差异过大。

三个类别分别建批次：

```text
food
daily
electronics
```

不能只用第 55 次涉及的电子类设计恢复位姿。运行时出现 `unknown` 或零检出时，系统并不知道眼前是哪一类物块，因此恢复位姿必须对三个类别通用，不能按照真实类别选择动作。

物块 yaw 第一阶段保持与正式生成器一致的 `-1.5708`。任意角度旋转可以作为额外鲁棒性实验，但不能与当前正式刷新分布混在同一个准确率结论中。

## 6. 避免对第 55 次样本过拟合

### 6.1 第 55 次只作为回归锚点

第 55 次坐标应满足两个用途：

1. 正常观察位姿下确认问题能否重复出现；
2. 恢复位姿确定后，确认该已知失败条件是否被修复。

它不应占据大部分开发样本，也不应作为唯一验收样本。否则可能得到一个只对 `(-0.935, -0.658)` 有效、却把其他边界位置移出视野的观察位姿。

建议把精确第 55 次坐标及其小邻域样本限制在开发集的约四分之一以内，其余开发样本覆盖整个 seq35 区域。

### 6.2 采用空间分层而非只测一个角落

将 seq35 区域归一化为：

```text
u = (x - x_min) / (x_max - x_min)
v = (y - y_min) / (y_max - y_min)
```

并至少覆盖以下空间层：

- 中心；
- 四个边中部；
- 四个角附近；
- 第 55 次精确坐标；
- 第 55 次附近但不相同的坐标；
- 区域内部随机坐标。

开发集可使用一个显式网格，例如 `u、v ∈ {0.05, 0.50, 0.95}`，而验证集使用未参与调参的交错位置和连续随机位置，例如 `u、v` 接近 `0.25、0.75`，再叠加固定种子的分层随机样本。开发集和验证集不能使用完全相同的坐标表。

边界点建议保留少量内缩，避免浮点误差使模型中心越出原始合法刷新范围。内缩量和理由必须写入清单。

### 6.3 在设计恢复位姿前冻结验证集

推荐顺序：

```text
预先生成开发集与验证集清单
→ 封存验证集清单及随机种子
→ 只运行并查看开发集
→ 根据开发集失败分布设计恢复位姿
→ 冻结恢复位姿和判定规则
→ 一次性运行验证集
→ 不再根据验证集结果回头修改同一方案
```

如果验证失败后确实需要再次修改，应建立 `方案 B` 和新的验证集，而不是继续把原验证集称为未见数据。

### 6.4 按类别平衡，而不是用类别作为恢复提示

开发集和验证集都应平衡三类物块。每个空间层中三类样本数应尽量一致。最终至少报告：

- 每个类别的首次识别率；
- 每个类别的恢复成功率；
- 每个空间层的首次识别率；
- 每个空间层的恢复成功率；
- 类别 × 空间层的失败分布。

如果一个恢复位姿只改善电子类、却降低食品或日用品识别率，则不能作为通用 seq35 恢复位姿。

### 6.5 重复试验用于分离位置问题和随机问题

RGB-D 同步、OCR、导航停车误差和 Gazebo 时序都可能产生轮间变化。不能因为一个坐标成功一次就认定该位置可靠。

建议小样本阶段对每个关键坐标至少重复 3 次；已知失败点、四角和恢复位姿候选可重复 5 次。每次必须重新从 seq34 导航到 seq35。连续采集的 5 个 OCR 帧属于同一个试验单位，不能当成 5 次独立成功样本。

### 6.6 禁止按结果挑选样本

下列做法会造成明显过拟合或结果偏高，必须避免：

- 只保留画面清晰的轮次；
- 删除正常启动但识别失败的轮次；
- 一直重跑某个坐标直到成功，再只记录最后一次；
- 看过验证集失败图片后继续微调并仍使用同一验证集；
- 将恢复位姿的每次尝试分别算作独立成功机会；
- 只报告综合成功率，不公开类别和区域分层结果。

### 6.7 使用独立端到端复核

恢复位姿在 seq34→seq35 压力测试中通过后，还应运行一组完整路线的端到端复核。该复核使用新的随机种子和未见坐标，确认：

- 完整路线的停车误差没有引入新的盲区；
- 恢复动作不会破坏机械臂或抓取状态；
- 增加的时间没有触发任务超时；
- 恢复后得到的三维坐标仍可用于抓取。

## 7. 首轮小样本压力测试

首轮目标是绘制失败分布，不是立即宣称最终准确率。建议每个类别单独运行，采用同一套位置集合：

1. 区域中心；
2. 四个边中部；
3. 四个角附近；
4. 第 55 次坐标；
5. 第 55 次附近若干偏移点。

为控制成本，可以先每点运行一次；对出现失败、低置信度、贴边或明显停车误差的点追加到预先规定的重复阶段。追加规则应在观察结果前写好，例如“任何首次失败点统一再做 4 次”，避免只对主观感兴趣的样本追加测试。

首轮暂时只使用当前正常观察位姿：

```text
[0.0, 0.10, 0.55, 2.10, 0.0]
```

在首轮完成前不加入恢复位姿，避免边采样边改方案导致数据不可比较。

## 8. 图片与诊断数据保存

### 8.1 每个试验目录

建议目录结构如下，实际根目录由用户后续指定：

```text
<output-dir>/
  manifest.csv
  summary.json
  cases/
    case_000001/
      metadata.json
      navigation.log
      attempt_normal/
        rgb_01.png
        depth_01.png
        annotated_01.png
        ...
        frames.json
      attempt_recovery_01/
        ...
```

失败时应保存该次定位请求使用的全部同步帧，而不是仅在失败结束后另拍一张照片。后拍照片可能已经处于不同时间、不同姿态，无法解释真实失败。

存储空间允许时，压力测试建议保存全部成功和失败帧；至少也应保存全部失败帧、全部低置信度帧，以及每个类别和空间层的成功对照样本。

### 8.2 图像数据

每一帧建议保存：

- 原始 RGB；
- 原始深度，使用可保留数值的格式；
- 便于人工查看的深度可视化图；
- OCR 检测框、类别框和置信度标注图；
- OCR 输入裁剪或多尺度输入；
- 原始 OCR 文本行、文本框和置信度；
- 最终类别、类别置信度、接受/拒绝结果。

### 8.3 几何与状态数据

每个试验至少记录：

| 类别 | 字段 |
| --- | --- |
| 试验身份 | case_id、阶段、批次、重复编号、随机种子 |
| 软件状态 | Git commit、工作区是否有未提交修改、关键配置文件哈希 |
| 物块真值 | 模型名、类别、请求坐标、Gazebo 实测坐标和 yaw |
| 导航起点 | seq34 的请求位姿、Gazebo 位姿、AMCL 位姿、协方差 |
| 导航终点 | seq35 的 Gazebo 位姿、AMCL 位姿、位置误差和 yaw 误差 |
| 机械臂 | 请求关节位置、实测关节位置、是否达到容差 |
| 感知 | 每帧 bbox、文本、置信度、有效深度像素、三维点 |
| 稳定性 | 有效观测数、类别票数、点云/三维坐标 spread |
| 恢复 | 触发原因、恢复位姿编号、恢复耗时、是否挽救成功 |
| 抓取 | 对齐次数、最终抓取点、attach 状态、抬升确认结果 |
| 最终结果 | 首次识别、恢复后识别、分类正确、抓取成功、错误码 |

还应计算物块文字框相对图像四边的最小像素间距。该字段能够直接检验“第 55 次因贴边裁切失败”的假设。

## 9. 失败分类

压力测试脚本或后处理应将失败划分为以下互斥的首要原因：

```text
NO_TEXT_BOX             未检测到文字框
CLASS_REJECTED          有文字框但类别未知或低于阈值
DEPTH_INVALID           OCR 有效但框内深度不足
TF_FAILED               三维点坐标变换失败
VOTE_UNSTABLE           有有效帧但类别票数不足
POSITION_UNSTABLE       类别稳定但三维点离散过大
NAVIGATION_FAILED       seq34 到 seq35 导航失败
ARM_POSE_FAILED         机械臂未达到观察位姿
GRASP_FAILED            识别定位成功但抓取失败
INFRASTRUCTURE_ERROR    ROS/Gazebo/进程基础设施错误
```

现有日志中的统一 `0 valid observations` 信息不足以区分 `NO_TEXT_BOX` 与 `CLASS_REJECTED`，后续保存逻辑应把 OCR 检测框是否存在作为单独字段。

## 10. 恢复观察位姿设计

### 10.1 设计时机

先完成首轮正常位姿小样本测试，再根据失败图片的空间分布设计恢复位姿。不能只看到第 55 次一个坐标就直接确定关节偏移量。

### 10.2 设计原则

恢复位姿应满足：

- 类别无关；
- 只在正常观察失败后触发；
- 优先使用一个备用位姿；
- 能覆盖一个连续失败区域，而不是一个像素级特例；
- 不显著增加机械臂碰撞风险；
- 恢复后的三维定位精度仍满足抓取要求；
- 不通过降低分类阈值换取表面成功率；
- 不读取 Gazebo 真值来决定运行时向哪边扫描。

如果失败主要集中在画面同一侧，可先测试机械臂底座关节或相机相关关节的小角度偏转，使该侧物块回到画面中央。如果相反两侧都存在盲区，再考虑两个有固定顺序的备用位姿。

### 10.3 推荐触发逻辑

正式补救逻辑可按下列顺序设计：

```text
正常观察位姿
→ 正常识别成功：继续分类、定位和抓取
→ 正常识别失败：保存完整失败证据
→ 移动到 seq35 专用恢复位姿
→ 恢复识别成功：继续定位和抓取，并标记 recovered
→ 恢复识别仍失败：返回对象未找到并保留全部数据
```

类别稳定但不是目标类别不属于“识别失败”，不得因此触发恢复扫描。恢复扫描针对的是无框、未知类别、深度无效或稳定性不足等感知失败。

### 10.4 成对评价

恢复位姿的主要指标不是单独图片识别率，而是：

```text
首次成功率 = 正常位姿直接成功的试验数 / 全部有效试验数

条件挽救率 = 正常位姿失败但恢复位姿成功的试验数
             / 正常位姿失败的试验数

最终成功率 = 正常位姿成功或被恢复位姿挽救的试验数
             / 全部有效试验数
```

同一轮中的正常观察和恢复观察属于一个试验，不能分别计入两个分母。还应单独报告恢复造成的平均和最大额外耗时。

## 11. 验证与统计解释

### 11.1 主要统计单位

统计单位是一轮从 seq34 出发的试验，而不是 OCR 帧。连续 5 帧共享相同物块位置、停车误差和光照状态，不能视为 5 个独立样本。

报告中至少提供：

- 样本数；
- 成功数和失败数；
- 观测成功率；
- 95% 二项分布置信区间；
- 每类别结果；
- 每空间层结果；
- 正常位姿和恢复后结果；
- 所有失败 case_id 及其证据目录。

### 11.2 “逼近 99%”与“证明达到 99%”的区别

少量样本得到 99% 左右的点估计，不等于已经以高置信度证明真实成功率达到 99%。例如在独立验证中，即使观察到零失败，按常用的“零失败三法则”，约需要 300 个独立样本，才能把 95% 置信水平下的失败率上界压到约 1%。

因此小样本压力测试的用途是发现盲区和比较方案，不应用来单独宣称 99% 的总体可靠性。最终结论应同时呈现正式 200 次实验、压力测试分层结果和独立验证结果。

### 11.3 建议验收条件

恢复方案进入正式任务前，至少满足：

1. 独立验证集中的最终识别率高于正常位姿首次识别率；
2. 三个类别均受益或至少没有出现明显退化；
3. 第 55 次坐标及邻域能够稳定恢复；
4. 未参与调参的其他边界区域没有新增集中失败；
5. 没有增加类别误判；
6. 恢复后的三维坐标 spread 和抓取成功率满足现有要求；
7. 额外耗时不触发任务超时；
8. 完整路线端到端复核通过。

## 12. 推荐实施顺序

```text
阶段 A：冻结并完成正式 200 次实验，不改变当前运行参数

阶段 B：新增独立 seq35 压力测试脚本

        冻结关节值、触发条件和重试次数

阶段 E：运行此前封存的独立验证集
        统计首次成功率、条件挽救率和最终成功率

```

该顺序可以同时满足两点：正式 200 次实验保持可比性；seq35 的补救方案又能以独立、可复查的方式验证，而不是针对第 55 次单个失败样本做特例修补。
