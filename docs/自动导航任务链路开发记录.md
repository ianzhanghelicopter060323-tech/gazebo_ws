## 1. 本次开发范围

本次只搭建完整比赛工程骨架，并实现第一阶段任务：

> 接收任务 → 检查导航与定位状态 → 获取抓取区前置点 → 调用 `move_base` 导航 → 返回到达结果

感知、物块抓取、运输、放置和外部通信暂未实现，只保留对应目录和后续扩展入口。

## 3. 已实现的导航任务链路

小车端或测试端通过 `/sim_task/execute` 发送
`smart_factory_interfaces/ExecuteTaskAction`，任务中包含：

- `task_id`：任务唯一标识；
- `target_class`：目标类别，当前支持 `FOOD`、`DAILY`、`ELECTRONICS`。

当时任务节点直接依次执行以下步骤；当前 Mission 保留相同业务阶段，但定位与
导航步骤通过 `NavigateAction` 委托给 `smart_factory_navigation`：

1. 检查任务编号和目标类别；
2. 等待 `/move_base` Action 服务；
3. 检查 `/amcl_pose` 是否新鲜、协方差是否在阈值内；
4. 检查 `map → base_footprint` TF；
5. 读取抓取区前置点；
6. 向 `/move_base` 发送标准 `MoveBaseGoal`；
7. 处理成功、超时、失败、重试和任务取消；
8. 成功后返回 `ARRIVED_PICKUP_STAGING`。

任务状态同时发布到 `/sim_task/state`。当前架构中 Mission 不直接发布
`/cmd_vel`；普通路线由 `move_base` 输出速度，必要的航向与抓取前底盘对齐由
Navigate Action Server 管理。正式链路仍不读取 Gazebo 的模型真实坐标。

## 4. 抓取区前置点坐标

坐标配置文件：

```text
src/smart_factory_mission/config/pickup_staging_dev.yaml
```

当前保持未配置状态：

```yaml
pickup_staging:
  configured: false
  frame_id: map
  # x: TODO_MEASURE_IN_RVIZ
  # y: TODO_MEASURE_IN_RVIZ
  # yaw: TODO_MEASURE_IN_RVIZ
```

在 RViz 中用 `2D Nav Goal` 选择经过验证的安全停靠点，可用下面的命令查看目标：

```bash
rostopic echo /move_base_simple/goal
```

记录 `x`、`y` 和航向角 `yaw` 后填入配置文件，并将 `configured` 改为
`true`。`yaw` 的单位为弧度。未完成配置时，任务节点会明确拒绝导航，
不会把缺失坐标当作 `(0, 0)`。

这个固定坐标只用于当前开发阶段，后续比赛版本应由场景配置或感知结果动态提供。

## 5. 启动与测试

编译：

```bash
cd ~/gazebo_ws
catkin_make
source devel/setup.bash
```

启动当前阶段：

```bash
roslaunch smart_factory_bringup nav_to_pickup_stage.launch
```

坐标配置完成后，发送测试任务：

```bash
rosrun smart_factory_tests send_navigation_task.py \
  --task-id nav_demo_001 \
  --target-class food
```

`full_competition.launch`、感知服务和固定抓取能力已经落地；运输、放置和外部任务
通信仍是后续工作。以上原始清单保留用于说明项目从第一阶段演进到当前架构的过程。
