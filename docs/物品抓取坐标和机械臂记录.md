## 固定姿态导航对位抓取方案（2026-08-05）

保留现有 close_navi、mid、far_navi 识别位置和机械臂观察位姿。OCR 识别目标后，由深度相机计算物块三维位置；机械臂使用预先验证的固定预抓取、下探抓取和抬升姿态，不在线求解不同抓取形态。

根据物块位置动态计算底盘目标，通过 `move_base` 小范围调整机器人，使物块落入夹爪固定抓取点，同时给机械臂留出运动余量。导航停稳后重新读取深度并确认物块进入抓取窗口；必要时再修正 1～2 次，随后执行固定抓取序列。

## 两套仿真并行采集（2026-08-05 已验证）

同一份工作区和配置可以同时运行两套仿真，无需复制工作区。隔离的关键是为每套仿真使用不同的 ROS Master、Gazebo Master、日志目录和采集输出目录。否则 `/gazebo/*`、`/sim_task/*` 和 `/move_base` 等同名节点、话题和参数会互相干扰。

已经在默认端口 `11311` 上运行的第一套仿真保持不动。新建终端，用以下命令启动第二套无界面仿真：

```bash
source /home/ianichinose/gazebo_ws/devel/setup.bash

export ROS_MASTER_URI=http://127.0.0.1:11312
export GAZEBO_MASTER_URI=http://127.0.0.1:11346
export ROS_LOG_DIR=/tmp/smart_factory_sim_b/roslog
export GAZEBO_LOG_PATH=/tmp/smart_factory_sim_b/gazebo

mkdir -p "$ROS_LOG_DIR" "$GAZEBO_LOG_PATH"

roslaunch -p 11312 smart_factory_mission mission.launch \
  gazebo_gui:=false \
  start_rviz:=false
```

第二套仿真的采集脚本、监视脚本和任务发送器也必须在新终端中设置相同的 Master 地址：

```bash
source /home/ianichinose/gazebo_ws/devel/setup.bash
export ROS_MASTER_URI=http://127.0.0.1:11312
export GAZEBO_MASTER_URI=http://127.0.0.1:11346

# 按需运行采集或监视脚本，例如：
rosrun smart_factory_tests monitor_navigation_safety.py
```

如果监视脚本正在前台运行，可再开一个设置了相同环境变量的终端发送任务：

```bash
source /home/ianichinose/gazebo_ws/devel/setup.bash
export ROS_MASTER_URI=http://127.0.0.1:11312
export GAZEBO_MASTER_URI=http://127.0.0.1:11346

rosrun smart_factory_tests send_navigation_task.py \
  --task-id sim_b_001 \
  --target-class food
```

可在执行采集前用以下命令检查当前终端连接的实例：

```bash
echo "$ROS_MASTER_URI"
rosparam get /run_id
rosnode list
```

不要在第一套仿真正在采集的终端中修改 `ROS_MASTER_URI`，也不要让两个采集进程写入同一个输出文件或目录。两套并行时建议关闭 Gazebo GUI 和 RViz，以减少 CPU、内存和 GPU 占用。

## 识别与固定距离抓取联调记录（2026-08-06）

当前自动流程按 `35 -> 36 -> 37` 检查候选物块。35 或 36 只有在 5 帧 RGB-D 中至少 3 帧形成稳定定位并且类别明确不等于任务类别时才继续；未知或不稳定识别不会被当作“非目标”。35、36 都确认不是目标后，37 按排除法直接选中，但仍用 OCR 框和深度进行定位。

固定抓取姿态 `[0.0, 1.5, 1.4, -1.0, 0.0]` 下，无 GUI 仿真测得：

- `base_footprint -> tcp_link` 平移约为 `[0.356, 0.000, 0.018] m`；
- 因此目标中心到机器人基座的固定前向距离为 `0.356 m`，不能把底盘直接导航到物块坐标；
- 三个点位的深度表面点相对方块中心前向误差约为 `+0.011、+0.011、-0.003 m`，运行配置采用 `-0.005 m` 有符号补偿；
- 精对位最多接受 `0.25 m` 的视觉修正，并最多停下重观测两次；
- 小范围修正保持实测底盘朝向不变，仅使用全向底盘低速平移，闭环停止带为 `8 mm`；普通点位间导航仍由 `move_base` 完成。

抓取动作顺序固定为：机械臂处于观察姿态并完成目标选择后，先把夹爪张开到 `1.5`；完成底盘对位和再次定位后，下探到固定抓取姿态；等待 `/grasp_attach/ready == true` 后闭合到 `0.76`；确认 `/grasp_attach/state == GRASPING` 后才抬升，并在抬升后再次确认没有丢失物块。

无 GUI 集成结果：

- seq35 目标：初始视觉修正 `81 mm`，最终成功抓取并抬升；
- seq37 目标：seq35、seq36 均稳定识别为非目标后到达 seq37，视觉修正 `129 mm + 19 mm`，最终成功抓取并抬升；
- 两次成功结果均为任务阶段 `OBJECT_GRASPED (14)`，抬升后状态保持 `GRASPING`；
- 橙色相机标定方块在 `mission.launch` 中默认关闭，未参与以上测试；比赛随机物块脚本 `car3/scripts/spawn_cubes.py` 未修改。
